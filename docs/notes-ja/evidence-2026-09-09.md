# 2026-09-09 の到達点 ── 解消コード本体のレビューと、コーパスの取りこぼし

前回（09-07）のレビューはパッケージとスイープ基盤だけを対象にしていた。**主張そのものを
生んでいるコード**（`qh.m2`、`certify.m2`、`corpus.m2`、`StackyFan.m2`、
`scripts/verify_cofactors.py`）は見ていなかったので、そちらにかけた。指摘は 11 件、
**全件が実在**したので全件直した。

## 1. 結論に影響しうる 4 件

**`multSF` が退化した錐に重複度 0 を返す。** 射線が一次従属な錐では最大小行列式のイデアルが
零になり、重複度が 0 になる。Algorithm A の A1 も B の B1 も「重複度 > 1」で絞るので、
その錐は**飛ばされ**、ループは「完了」と報告する。滑らかでない扇に対して成功を返す経路である。
`rank` で拒否するようにした。パッケージの `coneMultiplicity` にも同じコードがあったので両方。

**センチネル `-1` が個数として使われていた。** `qh.m2` の `dP` は正次元の層成分に対して `-1` を
入れるが、下流では乗数として使われる。とくに `toList(-1 : chain)` は M2 では**エラーにならず
`{}` を返す**ので、腕が予測から黙って消える。同様に残余次数の切り捨て除算（式は厳密な等式の
はずなので、割り切れなければ前提が崩れている）と、`df` の重みが食い違ったときの警告も、
判定に届いていなかった。予測が信用できない理由を集め、ひとつでもあれば **`PREDICT-FAIL`**
という別の判定にした。根拠のない一致を CONFIRM と呼ばないためである。

**`toricResolve` の固有性判定がまだ乱択だった。** 20 点を撒いて、複数の錐に覆われた点を
「無害」と数えていた。極大錐が全次元で重なるという、この判定が捕まえるべき失敗そのものが
素通りする。`refinesOrthantExact` に差し替えた。

**独立検証器が変数名を捨てていた。** `verify_cofactors.py` は指数を添字だけでキーにしていたので
`xx_0` と `yy_0` が同じ変数だった。現状は単一の変数族しか現れないので潜在的だったが、
独立検証を名乗る以上ここは直す。あわせて、この検証器が**何を証明していないか**を docstring に
明記した。証明書に書かれた h_i が本当に主張対象のイデアルの生成元かは検査していない。

## 2. 残り 7 件

`certify.m2` が未知のサンプル名を黙って捨てて exit 0 になる、変数記号が 7 個で `take` が黙って

見ていない（路＋孤立した閉路も端点 2 つ）、など。

- **判定が変わった行：0**

## 4. ただしコーパスは 416 件ではなく 440 件だった

24 件の判定は CONFIRM 23・SKIP 1 で、他と整合する。**正しい完全な内訳は次のとおり。**

# 同日追記：L2 経路の出典と、非退化判定の誤り

## 6. Varchenko を探しに行って、もっと良い出典が見つかった

L2（トーリック）経路の一般的な正当化は `[D]`（自分の導出「Varchenko の証明は Jacobi 判定しか
使わないので任意標数で通る」）のままだった。原論文を読む前に検索したところ、**任意標数で
述べられた published な定理**が見つかった。

> **Aroca, F., Gómez-Morales, M., Mourtada, H.**, *Groebner fan and embedded resolutions of
> ideals on toric varieties*, Beitr. Algebra Geom. (2023); arXiv:2202.10874, **Theorem 1.3**
>
> Newton 非退化イデアル J、Gröbner 扇と両立する正則細分 Σ に対し、π_Σ : X_Σ → X_σ は
> proper birational で、全変換の既約成分は smooth（特に strict transform が smooth）、
> かつ transversely に交わる。

要旨に「without assumptions on the characteristic of the base fields」と明記。
**L2 の根拠は `[D]` から `[F-AI]` に上がった。** Varchenko は不要になった。

射程と仮定：**K は perfect field**（§2 冒頭に明記。非完全体は射程外）。Remark 1.4 により
主張は O の近傍で局所的。イデアルに対する主張なので `toricResolveIdeal` も覆い、
「transversely」まで言うので SNC も含む。

## 7. その過程で、我々の非退化判定が定理の仮定より粗いことが分かった

定理の非退化（Def 1.2）は「**すべての v ∈ σ** について Sing(V(In_v(J))) ∩ T = ∅」。
ところが `qh.m2` は**座標を 0 にした制限 f_J** しか見ていなかった。これは strictly 粗い。

witness：f = x²y + y²z + z²x の Newton 多面体が選ぶ初期形式は **7 個**あるが、座標を 0 に
して得られるのは **4 個**だけ。辺に対応する x²y+y²z、x²y+xz²、y²z+xz² の 3 面は一度も
検査されていなかった。

`Polyhedra` を使い、Γ₊ のファセット内向き法線の部分和を v として走らせることで**全ての
初期形式を厳密に列挙**する実装（`initialForms`）に差し替えた。witness で 7 面ちょうどを返す。

**再実行した結果、440 件すべてで判定も `nondeg` も変わらなかった。** 粗い判定は、このコーパスに
関してはたまたま十分だった。ただし一般には十分でないので、修正は必要だった。E_8（標数 2）は
4 面 → 7 面の検査になり、依然として非退化。

## 8. 途中で自分が入れたガードがランナーを壊した

§4 で足した完全性チェックのために `for name in $(M2 ...)` を `for name in $wanted` に
書き換えたが、**zsh はコマンド置換は単語分割する一方、パラメータ展開は分割しない**。
ループが 1 回しか回らず、全サンプル名を連ねた 1 個の文字列が CRASH 行として書き込まれ、
集計が壊れた。不完全な実行を検出するためのガードが、その実行自体を壊した形である。
`#!/bin/sh` に変更して解決（理由をスクリプト内にコメントで残した）。

## 9. 2 経路と非退化性の関係（整理）

| | P2（重み付き blow-up ＋ Bergh） | P1（トーリック経路 L2） |
|---|---|---|
| 非退化性 | **不要** | 事前保証には必要（AGM Thm 1.3） |
| 与えるもの | 解消の**存在** | 明示的な構成と**証明書** |
| 体 | 任意（M の仮定の下） | perfect |

**命題 M に非退化性は現れない。** P2 が使うのは「X ∖ {v} が k 上滑らか」だけである。
また**証明書の検証自体も非退化性に依存しない**。単位イデアルの補因子も壁の数え上げも厳密 LP も
事後的な検算であり、細分が実際に解消していれば証明書はそれを証明する。非退化性が要るのは
「細分すれば解消するはずだ」と**事前に**言うためだけ。

実測でも、粗い判定で退化と判定された A4 サンプル 780 件は P1 で全件解消できている。
保証の範囲外でも実際には動く、という観察。
